Core narrative

1. From Fragmented Glyphs to a Continuous Evolution Model

One page, one argument: problem → data → model → inference → evidence.

Oracle Bone decipherment is not just visual matching. A glyph may change sharply across Bronze, Seal, Clerical, and modern scripts while still belonging to one historical trajectory. MSEF models that trajectory directly instead of comparing isolated snapshots.

  1. 01Why direct matching fails. Intermediate dynasties can introduce non-monotonic visual shifts.
  2. 02Why the dataset matters. Complete five-era chains are scarce, but partial cross-era correspondences are abundant.
  3. 03What MSEF learns. Each glyph becomes an era-specific manifold point, and Neural ODEs learn how points move between eras.
  4. 04How inference works. CBED recalls candidates forward, removes unlikely or extinct paths, and checks candidates by tracing them backward.
  5. 05Why the result is inspectable. Post-analysis tests whether the model learned paleographic structure rather than shallow pixel similarity.

Dataset

3. Fine-Grained Cross-Era Supervision

The dataset is what lets MSEF learn from incomplete historical chains rather than requiring every character to survive through all eras.

The dataset preserves era, subperiod, regional, visual, structural, semantic, contextual, and spatiotemporal signals. This allows partial correspondences to become supervision for continuous dynamics.

  1. 01Cross-era coverage. Characters are linked across OBI, Bronze, Seal, Clerical, and Regular scripts when evidence is available.
  2. 02Fine-grained time. OBI groups and Bronze subperiods preserve within-era variation.
  3. 03Partial chains as signal. Non-complete pairs become usable under continuous manifold learning.
